# Участники сделки, замещение и Онлайн-запись

В проекте есть локальное приложение Bitrix24. Оно добавляет в карточку сделки вкладку **«Участники сделки»**. В ней менеджер назначает участников и передаёт клиента коллеге на срок отпуска. Передача меняет ответственного и фиксируется комментарием в таймлайне.

Приложение создаёт поля участников, замещения и технический ID ресурса Онлайн-записи, в том числе:

- `Подопечный` (`UF_CRM_CARE_RECIPIENT`);
- `Сиделка / исполнитель` (`UF_CRM_CARE_EXECUTOR`).
- `Исходный ответственный`, `Замещающий менеджер`, `Замещение до`, `Комментарий к замещению`;
- `ID записи Онлайн-записи` (`UF_CRM_CARE_BOOKING_ID`) — постоянная связь сменной сделки с записью в расписании.
- `Ручная фиксация связи с записью` (`UF_CRM_CARE_BOOKING_MANUAL`) — запрещает фоновой синхронизации восстанавливать связь, которую менеджер снял вручную.
- `ID ресурса сиделки`.

Заказчик использует штатное поле сделки `Контакт`, поэтому сохраняются обычные звонки, история коммуникаций и связи CRM.

## Установка

1. Откройте **Приложения → Разработчикам → Локальное приложение**.
2. Создайте приложение типа **Сервер** с названием `Участники сделки`.
3. В правах выберите `crm`, `placement`, `user_brief` и `booking`.
4. В качестве обработчика установки укажите:

   ```
   https://bl.tube-city.ru/api/bitrix/participants/install
   ```

5. Сохраните приложение. Установочная страница создаст поля и добавит вкладку `Участники сделки` в карточку каждой сделки.

## Работа менеджера

На вкладке нажмите нужную роль, найдите существующий контакт или создайте новый. Для новых контактов тип ставится автоматически:

- `Заказчик` — системный ID `CLIENT`;
- `Подопечный` — системный ID `SUPPLIER`;
- `Исполнитель` — системный ID `PARTNER`.

Приложение само переименовывает эти три отображаемых типа контактов в **Заказчик**, **Подопечный** и **Сиделка / исполнитель**. Системные ID не меняются: так не сломается текущая передача заявок с сайта.

Для уже созданного контакта приложение по умолчанию не изменяет его тип: это осознанно, поскольку тип относится к контакту глобально, а роль может отличаться от сделки к сделке. При необходимости менеджер включает видимый флажок изменения типа.

## Онлайн-запись

- при создании сделки лист ожидания не используется;
- при назначении подопечного его контакт становится клиентом записи;
- для всех сиделок используется один общий тип `Сиделка`, а ресурс получает уникальное имя `<ФИО> - <ID контакта из CRM>`, например `Люся Викторовна - 0102`;
- приложение сначала ищет ресурс по этому имени, затем умеет подобрать прежние варианты имени или старый ресурс по ФИО, если он не привязан к другому CRM-контакту; найденный ресурс переименовывается без создания дубля;
- если Bitrix сообщает о дубле после параллельного создания, приложение повторно читает каталог и использует уже появившийся ресурс; только что созданный ресурс повторно не обновляется;
- ресурсу сиделки назначается доступность 00:00–24:00 по Владивостоку каждый день; это окно планирования, а не длительность смены;
- в блоке **«Создать запись»** менеджер вводит название и время «с/до». Приложение само берёт подопечного и ресурс сиделки из текущей сделки, связывает запись с контактом подопечного и со сделкой;
- ниже формы показано **«Расписание»** на ближайшие 60 дней: только записи текущего подопечного на ресурсе назначенной сиделки. Список сгруппирован по датам, обновляется кнопкой и не смешивается с чужими сменами;
- внизу списка доступна кнопка открытия Онлайн-записи для просмотра или ручного изменения графика;
- каждая созданная запись содержит подопечного именно как клиента CRM: внешняя страница сделки ищет весь график по ID этого контакта, а не по ID ресурса или сделки;
- ресурс сиделки нужен менеджеру как колонка планирования и показывает, кто должен выйти на смену.

### Автосопоставление смен

После создания сменной сделки сервер проверяет записи Онлайн-записи и создаёт связь автоматически. Сервер рассматривает сделки из воронки `6`, у которых поле `UF_CRM_1787843951` равно ID основной сделки. Запись должна быть связана с этой же основной сделкой через `booking.v1.booking.externalData`, содержать того же подопечного и ресурс назначенной сиделки.

Время используется для выбора записи внутри основной сделки: начало смены должно совпадать с началом записи с допуском 5 минут или попадать внутрь периода записи. Окончание смены для первичной привязки не требуется, поэтому тестовая смена продолжительностью 15 секунд также связывается. Автоматически сохраняется только единственный кандидат.

Созданная связь сохраняется в `UF_CRM_CARE_BOOKING_ID`; при последующих изменениях времени она не перезаписывается автоматически. Непривязанные смены отображаются в блоке **«Спорные смены»** между формой создания записи и расписанием. Менеджер может выбрать смену, указать запись в модальном окне или снять существующую связь крестиком рядом со сменой в расписании. После ручного снятия фоновая синхронизация не вернёт старую связь сама.

Для появления технических полей после обновления приложения повторно откройте его установочную страницу.

## Замещение и очередь

Кнопка **«Передать клиента»** запрашивает нового менеджера, дату окончания и комментарий. Пока действует такое замещение хотя бы по одной активной сделке исходного менеджера, сервер исключает его из round-robin новых заявок. После окончания срока сделки автоматически возвращаются исходному ответственному.
