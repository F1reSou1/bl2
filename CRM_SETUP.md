# Bitrix24: настройка воронок для сайта

Сайт передаёт все формы на `POST /api/leads`. Сервер создаёт контакт и сделку в одной из двух категорий. Секретный вебхук хранится только в переменных Dokploy.

## 1. Воронка клиентов

Создайте (или переименуйте существующую) воронку сделок: **«Заявки с сайта — уход»**.

Рекомендуемые стадии отражают реальный путь семьи на сайте: `Новая заявка` → `Связаться с семьёй` → `Оценка ситуации и расчёт` → `Подбор сиделки` → `Согласование кандидатуры` → `Договор и первый выход` → `Уход начат`.

Для неуспешных заявок: `Отказ / не подошли условия` → `Причина отказа`.

В неё направляются:

- обратный звонок из всех продающих модальных окон;
- полный расчёт из калькулятора: выбранная услуга, цена, надбавки, возраст, пол, состояние подопечного, комментарий и выбранные ситуации.

Полный расчёт сохраняется в отдельном пользовательском поле сделки «Заметка с сайта». Так менеджер видит понятное описание заявки без технического JSON.

## 2. Воронка найма

Создайте вторую воронку: **«Кандидаты в сиделки»**.

Рекомендуемые стадии: `Новый отклик` → `Связаться с кандидатом` → `Собеседование и оценка опыта` → `Проверка документов и рекомендаций` → `Стажировка / первый выход` → `Кандидат в базе`.

Для неуспешных откликов: `Не подходит` → `Причина отказа`.

В неё поступает форма «Хотите работать у нас?» с именем и телефоном кандидата.

## 3. Секрет и идентификаторы

В этом портале уже созданы направления с ID `2` и `4`. Создайте входящий вебхук с правами CRM (сделки и контакты), затем в Dokploy добавьте переменные из `.env.example`:

- `BITRIX_WEBHOOK_URL` — полный URL входящего вебхука;
- `BITRIX_CLIENT_CATEGORY_ID=2` — «Заявки с сайта — уход»;
- `BITRIX_RECRUITMENT_CATEGORY_ID=4` — «Кандидаты в сиделки».
- `BITRIX_SITE_NOTE_FIELD=UF_CRM_1786668098223` — код пользовательского поля сделки «Рекомендация с сайта». Сайт записывает туда нормализованные данные калькулятора и форм, а не технический JSON в комментарий сделки.

Основная воронка имеет ID `0`; у новых воронок ID показывает Bitrix24 в настройках направления сделок. После сохранения переменных заново разверните Docker-сборку и отправьте по одной тестовой форме каждого типа.
